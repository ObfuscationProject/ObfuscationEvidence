POSIX and ABI repairs
The shared-anonymous pressure test incorrectly requested at least 768 pages
against a 661-page reserve-constrained user quota. It now allocates bounded
chunks until ENOMEM, verifies existing data, releases and reuses a chunk, checks
zero initialization and cleans up. The native harness requires this phase's
success marker. No quota or reserve was weakened to make the test pass.

The orphan test now waits for the implemented PID1 adoption contract, with a
monotonic deadline and a yielding sleep. Debug init reaps adopted children while
waiting for each acceptance application; orphan records no longer exhaust the
process table during subsequent checks.

Current object-pressure admission no longer requires ABI55 after passing the
shared ABI74 validator. It validates the complete current contract, exact compiler
identity and artifact hashes. Historical ABI-specific qualification receipts were
not relabelled. New FAT API headers must be explicitly hashed in the consumed SDK;
module ABI74 and UAPI0.16 layouts are unchanged.

Mounted FAT functionality
The Kernel owns FatFileSystem/FatNode and all filesystem mechanisms. The OS boot
extension mounts a supported whole-volume Virtio FAT disk below the archive root
at /media. It uses the checked FAT boot parser, so the optional FAT32 type label
is not required; full provider admission still validates the volume. Recognized
invalid media fails admission without formatting. Ext4 root selection is retained.

Supported operations include ASCII case-insensitive lookup, FAT32 long names and
8.3 aliases, exFAT checksummed entry sets and allocation bitmap, NoFatChain file
handling, file read/write and zero-filled gaps, truncate, mkdir/list, unlink/rmdir,
retained unlinked descriptors and ordinary fsync. The sync utility now accepts an
explicit file/directory path; sync /media reaches the data filesystem. Its previous
no-argument system-root behavior is retained.

The implementation is explicitly bounded: 512-byte logical sectors, at most
128 sectors per cluster, 262,144 data clusters, 1,024 clusters per chain, 128 live/
retained/exposed node identities, and 31-character ASCII components. Permissions
are fixed root-owned 0644 files/0755 directories (readonly attributes remove write
bits). Other requested modes/owners fail before mutation. Rename, hard links,
symlinks, general Unicode and maintained POSIX timestamps are not supplied by FAT.
Unexposed retired nodes recycle; borrowed identities remain tombstones. Hosted
coverage includes 512 create/delete cycles per format and retained-unlink release.

The tested SDK root is native-final/source/build/sdk; choose the exact
architecture/debug or architecture/release directory in the OS kernel_sdk option.
Installed SDK directories were not replaced. An older SDK lacking the new FAT
headers is rejected explicitly rather than silently using source fallbacks.

These limits and APIs are documented in:
  ../../ObfuscationKernel/docs/fs/FAT_MOUNTED_PROFILE.md
  ../../ObfuscationOS/docs/FAT_MEDIA.md

Additional correctness and security defects corrected
- Seven ext4 directory traversals now confirm eight header bytes remain before
  reading a record. Malformed regression cases reject with no backing writes.
- Raw ext4/FAT checks reject wrapping/huge indices, invalid geometry and declared
  volumes beyond backing storage. Failed admission does not publish partial state.
- BlockCache invalidates a replacement before a fallible device read and drops
  cached sectors after uncertain writes, preventing poisoned/stale cache hits.
- Stat-image parsing bounds block-size exponents before shifting; typed inventory
  and exact link-count controls reject malformed or ambiguous fixture inputs.
- FAT mount checks cycles, crosslinks, allocation ownership, mirrors, boot/entry
  checksums and supported names. I/O failure disables further writes. Eight
  injected write-failure boundaries per format pass the hosted controls.
- FAT32 long names and 8.3 aliases share one checked namespace. The reproduced
  alias collision is rejected, and new aliases avoid existing long names/aliases.
- The FAT guest harness rejects late failure markers and abnormal emulator exit
  codes, even after apparently successful phase/prompt output.

Evidence interpretation
Counts above measure different kinds of checks and must not be summed into a
standards or milestone completion percentage. Host models, actual QEMU user
programs and physical hardware are distinct. No physical machines were tested.
Guest acceptance uses maintenance consoles with login disabled; it is not a fresh
account-login or clean system-power qualification.
FAT is nonjournalled and does not support the stronger sync_persistent/clean-power
contract. Stop/start after guest fsync does not establish arbitrary power-cut,
torn-write or physical volatile-cache durability. Full POSIX, SMP/IRQ/DMA breadth,
all ext4 feature combinations and absence of all vulnerabilities are not claimed.
Hosted ASan runs disabled LeakSanitizer; they do not establish leak freedom.
Prior superseded/interrupted campaigns and their failures remain in place; use
only the final paths above for the final implementation result.
